# Heritability & Repeatability Audit of the ~200-Column Colony Feature Space, and Strain × Cu GxE for Color Traits

## Persona
**Quantitative Geneticist** — I decompose phenotypic variance into genetic vs. environmental vs. measurement components, ask whether a trait is heritable/repeatable before anyone draws biological conclusions from it, and look for genotype × environment (GxE) interaction wherever a stress gradient exists.

## Motivation
Every feature column in `v_phenotype` is treated as if it were equally trustworthy, but a quantitative-genetics frame asks a prior question: *how repeatable is this trait before we claim it means something?* The 16 replicate plates per Cu dose are effectively 16 "environs" per strain at fixed dose; the replicate colonies within a well are the measurement litter. That gives a clean variance hierarchy — strain (genetic) / plate (macro-environmental, nested in Cu) / well (micro-environmental) / colony (measurement) — which is exactly what repeatability ICC needs. The geneticist's punchline: if a feature's between-strain variance is swamped by plate or colony-within-strain noise, it is useless as a strain descriptor no matter how "significant" it looks pooled. Conversely, if HSV/xy/chroma, intra-colony StdDev/CoeffVar, or the Haralick texture set have high repeatability, they are untapped heritable phenotypes. Separately, the whole screen *is* an incomplete factorial GxE experiment (320 strains × 7 Cu doses, unbalanced), so strain × Cu reaction norms for color (not just extent) can be tested directly.

## Connection to Existing Data
- `v_phenotype` keying gives the full nesting: `strain_id`/`strain_code` → `run_number` → `plate_number` → `well_position` → `object_label`; `copper_mm` (0–30, 7 levels, 16 replicate plates/dose) and `hours_since_plate_start` (0–117 h). Per-colony and within-colony (Min/Q1/Mean/Median/Q3/Max/StdDev/CoeffVar) stats exist for ColorLab {L*,a*,b*}, ColorHSV, Colorxy, plus TextureGray (52 cols) and morphology — the ~170 unused columns.
- The existing **Cu × species fixed-effect F-test** on `log(max_area)` (F=4.34, p≈6e-4) established that species react to Cu; I extend this to the *strain-within-species* level and to *color* traits, with random-slope GxE. Species sensitivity log2 index exists (R. mucilaginosa −0.72 vs R. kratochvilovae −4.13), so reaction norms can be checked against tolerance ranking.
- `rate_area vs rate_int` r = 0.21 (two growth axes) and L*≈Intensity collinear (>0.99) mean the "growth axis" (shape/area) and "pigment axis" (chromatic a*/b*/HSV) are candidate *genetic* trait axes — I decompose whether their weak coupling is genetic or measurement noise.
- Pixi env confirmed: `r-lme4`, `r-lmerTest`, `r-broom.mixed`, `r-duckdb` available; **no emmeans / AICcmodavg / minpack.lm** — so contrasts come from `fixef()`/`vcov()` Wald tests, and selection-free variance-component reporting uses raw lmer/lme output rather than AICc model averaging.

## Approach

**Part A — Repeatability (ICC) audit across the feature space.**
1. Build a DuckDB-lite collapsed analysis table: for each `(strain_id, run_number, plate_number, well_position, object_label, copper_mm)` at a fixed late time window (use 100–110 h, or the 90–110 h window already trusted), aggregate each feature column to per-colony Mean (and keep StdDev/CoeffVar for the within-colony traits) — averaging over the few images inside the window. This mirrors `endpoint_colonies` in explore-plate-position but for all ~200 columns.
2. For each feature `y` (start with the 5 the project already trusts: `Shape_Area`, `L*/a*/b*`_Mean, intensity — as calibration known-GxE signals, then the unused set), fit via `lmer`:
   `y ~ copper_mm_f + (1 | strain_id) + (1 | run_number:plate_number) + (1 | well_position:plate_number)`, data restricted to that time window, residuals assumed Gaussian after a per-feature transform (log for Shape_Area, cube-root or identity for color).
   Define per-feature **repeatability ICC** = `Var(strain_id) / (Var(strain_id) + Var(plate) + Var(well) + Var(resid))`, and also report a **plate ICC** (`Var(plate)/total`) which guards against over-interpreting small-genetic signals swamped by plate effects (as the plate-position work already warned for L*).
3. Because plate detection/data completeness varies with Cu (explore-plate-position's detection curve), also fit *within* each `copper_mm` level for the color traits, so ICC is reported per dose rather than averaged across a range where measurement noise explodes at high Cu.
4. Rank the ~200 features by ICC. Cluster them (hierarchical, |Spearman r| distance) and ask which *minimal independent* features achieve ICC > 0.7 — the "heritable core" of the phenotype space. Warn (robust-analysis convention): N strains ~320, but strain ID within-species is the unit; use `lmerTest::ranova` or parametric bootstrap (via `simulate()`) for the strain-variance test rather than trusting naive Wald p-values on variance components.

**Part B — GxE: strain × Cu random slopes for color traits (ambitious extension of Part A).**
5. For traits with adequate ICC at Cu=0 (e.g., `a*`_Mean, `b*`_Mean, HSV Hue/Saturation, ChromaEstimatedMean, a texture feature like TextureGray_Entropy or SumVariance), fit the full reaction-norm model on per-colony means across all Cu:
   `y ~ copper_mm + (1 + copper_mm | strain_id) + (1 | run:plate) + (1 | well:plate)`.
   The random slope term is the GxE: strains whose color response to Cu deviates beyond measurement/plate noise. Test the slope-variance component by LRT between models with and without the random slope (REML=TRUE, lme4 only — no AICcmodavg). Report `corr(intercept, slope)` per trait: a strong negative correlation means high-color strains fade faster under Cu (trade-off); near-zero means color level and Cu reaction are independent genetic axes.
6. Because genus nests inside the data (Rhodotorula / Cystobasidium / Pseudomicrostroma within `species` within strain hierarchy is: strain is the leaf; species groups strains), refit the Part A mixed model with a model where the intercept is `(1 | species) + (1 | species:strain_id)`; report the species-level vs within-species share of genetic variance — this is the "grouping species inside strain at genus level" the balanced view asks for, and tells whether color axes are conserved at genus or strain-specific scale. Also test whether `origin`/`environment` (marsh_tidalflat/soil/plant/food...) predictors absorb strain variance when added as fixed effects.
7. Multi-trait decomposition: from per-strain predicted BLUPs (from Part A models at Cu=0), take `rate_area`, `rate_int`, `max_area`, `a*`_Mean, `b*`_Mean, and intra-colony `a*`_StdDev as a 6×6 genetic (strain-level) correlation matrix. Ask the sharp question the existing r=0.21 raised: is the growth-vs-pigment decoupling *genetic* (between-BLUP correlation ≈ r=0.21) or *measurement* (within-strain residual correlation dominating)? Compare between-strain vs residual covariance of `rate_area–rate_int` — analytic multi-trait variance decomposition in lme4 (fit the same two traits jointly as a bivariate model stacking rows, traits as fixed effects, `(trait | strain_id)` random).

## Expected Insights
- **An ICC-ranked, redundancy-corrected map of the ~200-col feature space**: we will learn which unused columns (HSV/xy/chroma within-colony, texture subset, intra-colony StdDev/CoeffVar) are heritable strain signatures at all, and which are essentially plate/measurement noise that should never be fed into downstream clustering. Expect the a*/b*/chroma and a subset of texture features to be the repeatable "pigment axis," while most intra-colony StdDev/CoeffVar features are likely low-ICC (noise) — but this specific claim is exactly what the audit tests.
- **Species- vs strain-level heritability share of color axes**: whether pigment morphs are conserved within *species* (intercept group variance large) or are idiosyncratic per strain. Given provenance (China/Italy/America) and the R. mucilaginosa tolerance outlier, there is prior heterogeneity to capture.
- **GxE reaction norms for color**: whether Cu shifts color (browning/bleaching) uniformly or strain-specifically beyond extent — a genuine H2 × E decomposition. The key quantity is the intercept–slope correlation sign.
- **Genetic vs measurement origin of the growth×pigment decoupling (r=0.21)**: direct answer to whether the two growth axes and the color axes are distinct *genetic* dimensions or a measurement artifact of the peak-slope phase issue already documented.

## Feasibility
- **Effort**: High (Part B); Medium (Part A alone)
- **Data ready**: Yes — everything lives in `v_phenotype`; the collapsed per-colony table already exists in spirit (`endpoint_colonies` for the trusted subset); the real work is writing the ~200-column aggregation and looping lmer fits
- **Methods available**: Standard tools (lme4/lmerTest/duckdb in pixi). Constraint: no emmeans/AICcmodavg — Wald contrasts via `fixef()/vcov()` and LRT-based variance tests are the required route; variance components read from raw `VarCorr()` output, which is honest albeit selection-unadjusted
- **Key risk**: Measurement noise at high Cu and low cell mass (detection curves degrade past ~20–25 mM) will depress ICC in exactly the dose range where GxE matters most; and the ~320 strains at 7 doses with unbalanced plates means variance-component estimates are optimistic without bootstrap — the audit could "discover" repeatability that is mostly within-species plate structure. Mitigate by per-dose ICC and by restricting GxE to Cu ≤ 20 mM where colony detection is trustworthy.

# Strain-Level Repeatability of Intra-Colony Pigment Heterogeneity (StdDev/CoeffVar) — the "Texture as Heritable Trait" Test on Cu=0 Plates

## Persona
**Quantitative Geneticist** — same lens, applied to the within-colony pixel distribution as the trait rather than the mean. I treat the first two moments of the per-colony pixel histogram separately, because variance (here: intra-colony heterogeneity) can be its own heritable phenotype independent of the mean.

## Motivation
Every prior analysis uses per-colony *Median* (or mean) L*/a*/b*. The pixel-level StdDev and CoeffVar columns in `v_phenotype` — intra-colony heterogeneity — are ignored, yet for colonies that are radially structured (thicker pigment edge, pale center) the StdDev is a biological feature, not noise: it quantifies spatial pigment allocation. Quantitative genetics has a long history of treating trait variance ("insectary/heterogeneity" or plasticity of a scalar) as a heritable phenotype. The replicated design makes this tractable: within a well, the replicate colonies give us between-colony repeats of the StdDev value, and the 16 replicate plates per dose give between-plate repeats — so the ICC of intra-colony StdDev can be estimated exactly like the mean, and a trait that is repeatable and genetically differentiated is a legitimate new phenotype.

## Connection to Existing Data
- `v_phenotype` carries, for every color space, both central (Mean/Median/Q1/Q3) AND spread (Min/Max/StdDev/CoeffVar/IQR) columns; e.g., `lab_a_std`/`lab_a_coeffvar`, HSV Saturation StdDev/CoeffVar, and the whole TextureGray* group which is literally intra-colony pixel textu. All currently unused (context line 63–67).
- `endpoint_colonies` in explore-plate-position already computed `lab_l_sd`, `lab_a_sd`, `lab_b_sd` at 117 h — so the per-colony StdDev values are already materialized for the trusted subset; the step here is to treat them as phenotypes and run the variance decomposition, exactly parallel to the mean-based ICC but for spread traits.
- Cu=0 plates (16 replicate plates, control) give a clean environment for the mean-reference ICC, avoiding the Cu detection-curve confounds. The `copper_mm = 0` filter makes this *immediately* runnable today.
- Pixi env: lme4/lmerTest available (no emmeans/AICcmodavg/minpack.lm) — fine, since we need Wald/LRT, not model averaging.

## Approach
1. From `v_phenotype` at `copper_mm = 0`, late window (117 h, matching `endpoint_colonies`), build per-colony rows with the spread phenotypes: `ColorLab_{L,a,b}_StdDev`, `ColorLab_{L,a,b}_CoeffVar`, HSV Saturation_StdDev/CoeffVar over Saturation_Mean, and a reduced TextureGray set (Entropy, SumEntropy, Contrast, AngularSecondMoment — the 4 the 52-col set reduces to). Log-transform spread traits (they are bounded non-negative).
2. For each spread trait `s`, fit the baseline interrogator — same model I would fit for any mean trait:
   `s ~ 1 + (1 | species) + (1 | species:strain_id) + (1 | run:plate) + (1 | well:plate)`.
   Report the strain ICC = `Var(strain)/ (Var(strain)+Var(species)+Var(plate)+Var(well)+Var(resid))`, side by side with the identical model on the corresponding Mean trait (e.g., `lab_a_mean`). The comparison is the whole point: a spread trait with ICC comparable to its mean is a real phenotype; one an order of magnitude lower is measurement noise and should be dropped from all later color-space clustering.
3. Genetic-signal check: LRT (`lmerTest::ranova` or bootstrap via `simulate()`) for the strain component against a model with only species+plates. Adversarial self-check (robust-analysis): confirm the ICC is not driven by plate structure by also computing ICC on the subset restricted to plates ≥ 3 replicates per strain (unbalanced here), and by splitting on `run_number` (5 imager runs) to confirm ICC is stable across runs rather than a run artifact.
4. Connect to the pigment axis: within the ICC-rank table, test whether intra-colony `a*`_StdDev (red heterogeneity) correlates across strains with `a*`_Mean (level) — if genetic correlation high, heterogeneity is a scaling artifact of intensity; if near zero, it is an independent heritable axis. Use the BLUP/mean-variance correlation from step 2's model.
5. Sensitivity: refit at a second window (70–80 h) to confirm the heritability of within-colony heterogeneity is not a late-time conflation with colony size or crowding (coalesced colonies would inflate StdDev spuriously); report ICC at both windows and flag any feature whose ICC flips.

## Expected Insights
- **First repeatability figures for the intra-colony spread traits**: we learn whether StdDev/CoeffVar color heterogeneity is a heritable, strain-describing phenotype or measurement jitter. If (as I expect for most spread traits but possibly exception for `a*`-StdDev or texture entropy) ICC is low, we have a principled reason to exclude them from color-space clustering — a concrete, publishable negative. If any ICC is high and genetically uncorrelated with its mean, it's a novel descriptor (e.g., "fringed" vs "uniform" colonies) worth chasing.
- **Heritability of texture**: whether Haralick entropy/sum-entropy are repeatable colony "patterning" traits for the 3 genera, a genuinely new axis orthogonal to L*a*b* medians.
- **A robustness check on the whole project**: since the mean-trait models here use identical syntax to the ICC audit, this delivers a clean answer to "can we trust the endpoint tables at all high-Cu?" by quantifying plate vs strain variance on the control plates where signal is cleanest.

## Feasibility
- **Effort**: Low–Medium (single mixed-model loop on an already-materialized endpoint table)
- **Data ready**: Yes — spreadsheet-level query on `copper_mm=0` `v_phenotype` (or reuse `endpoint_colonies.rds` which already carries `lab_*_sd`)
- **Methods available**: Standard tools — lme4/lmerTest/duckdb; no emmeans needed (Wald/LRT suffice); note AICcmodavg absent so no model averaging, which this design does not require
- **Key risk**: At late times colonies may coalesce/crowd within a well, inflating intra-colony *with-well* StdDev variance and biasing the residual term downward (ICC inflated). Mitigation: repeat at 70–80 h window and require ICC stability across windows; if a spread trait's ICC is window-fragile, report it as uninterpretable rather than heritable. Second risk: few strains have ≥3 replicate colonies at the well level on Cu=0, shrinking effective N for the well term.
