# Idea 1 (Ambitious) — The Intrinsic Phenotype Atlas: A Bootstrap-Stable Latent Map of the ~200-Feature v_phenotype Space

## Persona
**Latent-Space Cartographer** — Representation-learning / ML-engineer lens. I ask not "which single feature differs" but "what is the effective dimensionality of this phenotype space, how many independent axes carry the strain diversity, and are strains arranged as discrete stable clusters (morphs) or a continuous spectrum?"

## Motivation
Every existing analysis (control-late-timepoint tables, growth-rates, species sensitivity) cherry-picks 2–6 columns (`Shape_Area`, `ColorLab_L*/a*/b*Median`, `Intensity_MeanIntensity`), while the other ~170 columns — the within-colony heterogeneity stats (`*StdDev`, `*CoeffVar`), the HSV/xy/chroma families, the full `TextureGray_*` block, most shape descriptors — sit unused and unmeasured as *axes*. From a representation-learning view, a high-dimensional raw feature dump with massive internal collinearity (L* vs Intensity >0.99; 4-angle Haralick blocks; per-channel Min/Q1/…/Max sharing the same channel signal) is exactly the situation where a principled latent decomposition pays off: it tells us the *rank* of the phenotype space, the *identifiable* axes, whether pigment "morphs" exist as stable discrete clusters or only a continuum, and which features define each axis. It also gives a rigorous way to test whether species / origin / environment / Cu-response align with learned axes rather than with pre-chosen endpoints.

## Connection to Existing Data
- `v_phenotype` (DuckDB) gives the full ~200-col row-level layer: `Shape_Area`, `Shape_Extent`, `Shape_Solidity`, `Shape_Eccentricity`, `Intensity_MeanIntensity`, `Intensity_CoefficientVarianceIntensity`, `ColorLab_{L*,a*,b*}{Min,Q1,Median,Q3,Max,StdDev,CoeffVar}`, `ColorHSV_{Hue,Saturation,Brightness}{Median,StdDev,CoeffVar}`, `ColorLab_ChromaEstimatedMedian`, `Colorxy_{x,y}Median`, `TextureGray_{Entropy,Contrast,AngularSecondMoment,Correlation,...}-avg-scale05`, all keyed by `strain_id`, `species`, `run_number`, `plate_number`, `well_position`, `object_label`, `copper_mm`, `hours_since_plate_start`.
- The replicate design is `(plate, well)` = up to 4 independent colony objects per strain per `copper_mm` (explore_plate_position, 7577 colonies / 306 matched strains / ~117h endpoint). The control-late-phenotype analysis already established per-strain windows (70–80, 80–90, 90–110 h) with replicate colonies on `copper_mm = 0`.
- Known pitfalls to *design around*, not repeat: L*≈Intensity collinearity (`growth_rates`), the peak-slope phase artifact (use late windows, not early slopes), hue being circular (existing analyses compute arithmetic hue means — a latent model must linearize hue first), and plate identity nested in Cu (pool colony medians before modeling; keep `copper_mm` and `run_number` as test covariate columns, never as latent inputs).

## Approach
1. **Design matrix (per-strain-per-timepoint aggregation, median of colony medians).** Query `v_phenotype` for `experiment_name='Copper'`, `strain_id IS NOT NULL`. Select the ~180 feature columns (exclude Bbox_/Grid_/Metadata_/image_name keys; exclude `ColorLab_L*` variants *after* recording them as a hold-out check since L*≡Intensity). For each strain × time-window (use 70–80, 80–90, 90–110 h from the control analysis; endpoint 110–117 h as a fourth) × `copper_mm ∈ {0,15,30}`: (a) collapse each colony across time by taking the row-median per feature; (b) across the ~4 replicate `(plate,well)` colonies take the **median** → robust per-strain vector **X_strain** (n≈306 × p≈180). Emit a parallel dispersion matrix of within-strain MAD of colony medians and of median per-colony `*StdDev`/`*CoeffVar` to keep heterogeneity as features. Keep `species`, `origin`, `environment`, `copper_mm` as label columns only.
2. **Preprocessing / handling the collinearity.** Per-feature robust standardization (median/IQR, not mean/std). Then redundancy pruning: (i) keep only angle-averaged `TextureGray_*-avg-scale05`, drop deg000/045/090/135 members if |Spearman r|>0.95 to any kept member; (ii) drop `ColorLab_L*` block (r>0.99 with `Intensity_MeanIntensity`); (iii) linearize hue with `(cos h, sin h)` on `ColorHSV_HueMedian` (and Q1/Q3), not raw degrees; (iv) drop near-constant features (|CoeffVar|≈0). Expect p≈90–110. Always feed a Spearman-correlation (rank) matrix, which is scale- and outlier-robust for the heavy-tailed colony features.
3. **Latent decomposition (robust standardized PCA on the correlation matrix) + sparse/varimax rotation.** PCA on the rank-correlation matrix; number of axes by parallel analysis (permuted-data eigenvalue crossover) plus bootstrap eigenvalue CI (are PCs 1–k distinguishable from noise?). Rotate loading matrix with varimax (orthomax) so each axis is a sparse, named part (e.g., "lightness/density", "red↔yellow chroma", "texture/heterogeneity"). Project each strain into the rotated latent space; also project each strain's time-windows to trace **latent trajectories** (darkening/chroma-appearance in latent coords, not raw endpoints).
4. **Discreteness vs continuum — UMAP + HDBSCAN with cluster-stability bootstrap.** On the (rotated) latent coords (k≈10–30), run UMAP (fixed seed) → HDBSCAN. Bootstrap: resample strains 200×, recluster, compute pairwise cluster Jaccard; declare a "morph" only if its core memberships are stable across bootstraps. Report density landscape (continuum) if no stable clusters form — that negative result is itself the answer to the pigment-morph question.
5. **Validate on strain (not colony) splits + sanity axes.** (i) Split the **306 strains** 80/20; fit PCA(+rotation)/UMAP refit on train, project test strains *without* re-estimating loadings/HDBSCAN (assign to nearest stable core); score held-out **silhouette** and held-out **within-strain** distance: the same strain's two independent replicate-plate subsets (A/B split of colonies) must sit close in latent space (within-strain distance << between-strain). (ii) Check whether each latent axis separates `species` (R. mucilaginosa vs R. kratochvilovae/araucariae), `origin` (China/Italy), `environment`, and whether the Cu treatment shifts strains along a *directional* latent vector (0→30 mM) rather than scattering — a per-strain Cu-displacement vector in latent space, correlated with the extent-based sensitivity index from growth-rates but now in chromatic terms.

## Expected Insights
- The **effective rank** of the ~180-col space at strain level — the answer to "how many independent axes" (hypothesis: far fewer than 180, plausibly 10–30; and whether ~3–6 explain most between-species variance).
- Whether strains form **discrete, bootstrap-stable pigment morphs** (≥1 stable HDBSCAN core separated by hue/chroma) or a **continuum** — and which species/origin/environment map onto each axis. This converts the informal "yellow vs red vs pale colony" observation into a tested representation.
- **Which features dominate each axis** (rotated loadings): expectation is a lightness/density axis (L*/Intensity/Area), a chromatic axis (a*/b*↔Saturation↔Chroma↔xy), a green–red vs blue–yellow split, and a within-colony heterogeneity/texture axis (StdDev/CoeffVar, Haralick entropy) — i.e., heterogeneity-as-phenotype becomes a quantified axis rather than an ignored statistic.
- Whether Cu shifts are **chromatic (pigment-depleting)** vs merely **extent-related** — a latent-vector statement the endpoint tables cannot make.

## Feasibility
- **Effort**: High
- **Data ready**: Mostly — `v_phenotype` + `strain` metadata are in the DuckDB; needs targeted aggregation queries (one DataFrame per strain×window×dose) and the hue/angle linearization; replicate-plate A/B split requires care with the (plate,well) keying.
- **Methods available**: Standard tools (pandas/DuckDB, scikit-learn PCA/UMAP/HDBSCAN, statsmodels parallel analysis; ~200 bootstraps of n=306×~100 is cheap).
- **Key risk**: n=306 strains vs p≈180 starting features with massive collinearity → unstable rank estimation and UMAP/HDBSCAN artifacts; the dominant lightness/Area axis may swamp the subtle chromatic axes (mitigate by also running a chroma-block-only PCA as a within-idea sanity check); and if traits are truly continuous, cluster-stability bootstrap may legitimately return zero stable clusters — which is a finding, not a failure.

# Idea 2 (Tractable) — Parts-Based Decomposition of the Chromatic Block: NMF "Pigment Parts" on Saturation/Chroma/a*/b*/xy + Heterogeneity

## Persona
**Latent-Space Cartographer** — Representation-learning / ML-engineer lens focused on *interpretable, non-negative, parts-based* structure: if the carotenoid-relevant color signal (beta-carotene=orange/yellow, torulene=red, astaxanthin=red/pink) drives the data, then the right model is one that returns additive, non-negative "parts" whose loadings you can read as pigments — not signed, compressed eigenvectors you cannot sign-interpret.

## Motivation
The project's stated open direction is "structure of the 3-D+ color space … whether strains cluster into pigment morphs," and its real-world hook is that Rhodotorula are industrial carotenoid producers. A full-color-space PCA is useful but its signed, rotated loadings are hard to map onto "how much yellow vs how much red." NMF is the natural parts-based alternative: it factors the non-negative chromatic feature matrix into **additive pigment-like parts** with transparent loading patterns, a natural fit for a domain where colors literally mix. It also cleanly absorbs the within-colony heterogeneity stats (`SaturationStdDev`, `a*StdDev`, `b*CoeffVar`) as *additional parts* (heterogeneity-as-phenotype), which the L*/a*/b*-median-only analyses throw away. And unlike the ambitious full-atlas idea, it runs in an afternoon on a ~25-feature chromatic block.

## Connection to Existing Data
- `v_phenotype` chromatic columns used here: `ColorHSV_Saturation{Median,Mean,Q1,Q3,StdDev,CoeffVar}`, `ColorHSV_Hue{Q1,Median,Q3}` (linearized as sin/cos), `ColorLab_a*{Median,Q3,Min,StdDev,CoeffVar}`, `ColorLab_b*{Median,Q3,Min,StdDev,CoeffVar}`, `ColorLab_ChromaEstimated{Mean,Median}`, `Colorxy_{x,y}{Mean,Median,StdDev}` — all available per colony per image, keyed to replicate `(plate,well)` objects and `copper_mm`.
- `growth_rates` already established the facts this design leans on: L* is ~perfectly collinear with `Intensity_MeanIntensity` (so chromatic signal must come from a*/b*, Saturation, Chroma, xy — the block NMF uses), hue is circular (motivates sin/cos encoding), and the Cu effect is extent-limited with the *chromatic* side of the response still unquantified.
- The per-strain, `copper_mm=0`, late-window replicate-column aggregation is already proven by the control-late-timepoint analysis (70–80 / 80–90 / 90–110 h windows, replicate colonies). The species-sensitivity analysis quantified Cu via *extent*, leaving the **chromatic response to Cu** open — NMF part-scores give exactly that quantity.

## Approach
1. **Design matrix (per-strain, Cu=0, late window).** From `v_phenotype`, for `experiment_name='Copper'`, `copper_mm=0`, take the 90–110 h window: median-of-colony-medians per strain over replicate `(plate,well)` colonies (as in Idea 1, but for the ~22 chromatic features listed above, plus their `StdDev`/`CoeffVar`). Build X ∈ R^(n≈306 × p≈22). Keep `species`/`origin`/`environment` as labels.
2. **Non-negative encoding.** Column-wise min-max to [0,1] for naturally non-negative features (`ColorHSV_Saturation*`, `ColorLab_ChromaEstimated*`, `Colorxy_x*/Colorxy_y*`); for signed `ColorLab_a*` and `b*` use **sign-split** `x_pos=max(x,0), x_neg=max(-x,0)`; encode `ColorHSV_HueMedian/Q3` as `(sin h, cos h)` then min-max. (No z-scoring — NMF needs a non-negative input.)
3. **NMF with sparseness + stability.** Fit scikit-learn NMF with L1-penalized (sparse) loading matrix W, k = 3…8; pick k by reconstruction-error elbow + cophenetic correlation, and — critically because NMF is rotation-variant — **bootstrap strains** (100 resamples), refit, and require each part's loading pattern to be stable (mean correlation of part-loadings across bootstraps > 0.8) before accepting it. Optionally anchor with a varimax-rotated PCA of the same (z-scored) block to confirm the parts are not NMF artifacts.
4. **Read the parts as pigments.** Name each part from its top loadings (e.g., a "yellow/orange" part loading on `b*Median`, `ChromaEstimatedMedian`, `SaturationMedian`; a "red" part loading on `a*pos` and `Hue sin`; a "pale/bleached" part loading anti-correlated to Chroma; a "speckled" part loading on `SaturationStdDev`/`a*StdDev`). Project strains to part-scores (H matrix).
5. **Validate on strain split + Cu-response probe.** (i) Fit NMF on 80% of strains, obtain W; score held-out 20% strains by projecting through fixed W and comparing part-scores to a full-data fit (correlation), and compute silhouette of `species` in part-score space vs a shuffled-label baseline. (ii) Interpretive check: part-scores should separate the known tolerant vs sensitive species from the growth-rates analysis, observed on Cu=0 only (intrinsic color). (iii) Probe: project per-strain `copper_mm ∈ {15,30}` colonies of the *same* strains through the Cu=0-learned parts; measure the per-strain shift in part-scores vs `copper_mm=0` as the **chromatic Cu-response vector**, and correlate it with the extent-based log2 sensitivity index — asking whether Cu depletes the red/yellow pigment parts.

## Expected Insights
- Whether ~306 strains' color variation **decomposes into a small number (<6) of stable, additive pigment-like parts** — a direct, interpretable test of the "morphs vs continuum" question in the domain's own terms (yellow/orange vs red vs pale + a heterogeneity part), with parts analogous to the three carotenoid classes (beta-carotene/torulene/astaxanthin) the group cares about.
- **Within-colony heterogeneity as a separate part** — whether speckled/non-uniform colonies form their own component, making heterogeneity a first-class phenotype instead of a discarded `StdDev` column.
- Whether `species`/`origin` separate on specific parts (e.g., R. mucilaginosa on the yellow/orange part) and, most novel, a **chromatic (not extent) Cu-response axis**: does Cu bleach the red part before it shrinks the colony?

## Feasibility
- **Effort**: Low–Medium (one aggregation query + a compact NMF script)
- **Data ready**: Yes/Mostly — all columns live in `v_phenotype`; the only preprocessing is the sign-split / sin-cos hue encoding.
- **Methods available**: Standard tools (scikit-learn NMF, Pandas/DuckDB); the bootstrap-stability loop of NMF over 100 resamples of ~306×22 is trivially fast.
- **Key risk**: NMF non-uniqueness (rotation/scale variance) could produce unstable or hard-to-name parts → mitigated by the loading-stability bootstrap; hue sin/cos and a*/b* sign-split can introduce artificial "blue-axis" parts if the sign-split is unbalanced; and with only ~22 features, collinearity within the block (Saturation vs Chroma vs b*) is high, so part names must come from **loading patterns** (stable across bootstraps), never from raw feature magnitude.
